# Reprise du projet par un nouvel assistant IA — texte prêt à copier

> Tu reprends le projet **PTD Coach** de Chimie ParisTech – PSL. Le dépôt Git qui t'est fourni est la **source de vérité**, et pas les conversations antérieures. Lis d'abord `AGENTS.md`, `docs/PROJECT_STATUS.md`, `docs/DECISIONS.md`, `docs/PRODUCT_SPEC.md`, `docs/PEDAGOGY.md`, `docs/PRIVACY_SECURITY.md`, `docs/ARCHITECTURE.md` et `docs/ROADMAP.md`. Identifie les décisions **VALIDÉES**, **PROPOSÉES** et les questions **OUVERTES**. Le but prioritaire est de développer **les compétences individuelles de management de projet** dans un projet collectif réel, avec IA individuelle privée, IA collective écrite sur écran partagé, tuteur humain qui voit des synthèses, et coordination transversale. Le référentiel à onze compétences est candidat, non validé. Ne manipule pas de données étudiantes réelles sans validation institutionnelle. Ne prétends pas que le backend ou les tests existent : le dépôt ne contient à ce stade que le cadrage documentaire. Commence par expliquer l'état du projet, les exigences pertinentes et un plan précis pour la tâche qui t'est confiée. Ne modifie pas silencieusement les principes validés. Pour toute modification, mets à jour les tests et `docs/PROJECT_STATUS.md`. Termine avec une passation vérifiable (fichiers modifiés, tests exécutés, choix et risques).

## Comment fournir le contexte

Partager le dépôt Git **privé** ou une archive du dépôt, pas une capture de nos échanges. Les quatre fichiers Word d'origine ne sont pas dans ce dépôt ; ils doivent être fournis par un canal autorisé si la tâche exige leur consultation. Leur existence et les éléments exploités sont décrits dans `docs/REFERENCE_MATERIAL.md`.

## Règle de décision

Si un nouveau modèle propose de modifier un principe de confidentialité, la finalité pédagogique, une compétence du référentiel candidat ou la pile technique, il doit proposer un ADR/une note de changement avec ses motifs. **Ne pas présumer l'accord.**
